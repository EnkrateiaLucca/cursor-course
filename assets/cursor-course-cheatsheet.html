Context management
  • Context windows are fixed (128k–1M tokens), and comprehension ≠ token count
  • Poor context → hallucinations. More context is not better: curate it
  • Use @-mentions for precision; start new chats often
  • Keep noise out of the index with .cursorignore
  • Prompt the diff: current state → desired state, with success criteria. "Make this better" has none
Project rules — .cursor/rules/
  • Always Apply — every session, automatically
  • Apply Intelligently — the AI decides when it's relevant (recommended)
  • Apply to Specific Files — pattern match, e.g. *.test.ts
  • Apply Manually — only when you @-mention it

Use for recurring mistakes, security patterns, team consistency. Keep each under 500 lines. Better context beats more rules. AGENTS.md (Cursor) and CLAUDE.md (Claude Code) carry project-level context.

Parallel agents on git worktrees

One clone, several working folders, each on its own branch, all sharing one .git history. Three agents → three folders → zero file collisions.

git worktree add ../auth feature/auth
# agent works in ../auth; review its diff
git worktree remove ../auth   # after merging

vs. git checkout: one folder, one branch at a time; stash first, rebuild after each switch.

MCP — Model Context Protocol ("USB for AI")

An open protocol connecting the AI to tools and data. A server exposes Tools (functions the AI runs), Prompts (templated workflows) and Resources (structured data).

  • GitHub — create PRs, review code, manage issues
  • Figma — extract design tokens, generate components
  • GitMCP — any repo as context: swap github.com → gitmcp.io
  • Databases — query and inspect PostgreSQL / SQLite
  • Playwright — the AI drives and sees your running app

Two-stage workflow

1. ChatGPT / Claude / Gemini — plan: brainstorm features, structure ideas, write context.md, plan the architecture.

2. Cursor — implement: generate code, multi-file operations, debug errors, refactor.

Iterative development loop
  1. Generate code with Agent
  2. Run the app: npm run dev
  3. Copy the error message into chat
  4. Let Cursor fix it, then review the change
  5. Commit the working state with git
Supabase backend in three moves
  1. Create a project at supabase.com; copy the API URL and anon key
  2. Add NEXT_PUBLIC_SUPABASE_URL and NEXT_PUBLIC_SUPABASE_ANON_KEY to .env.local
  3. Prompt: @docs/context.md + "install the Supabase client and create the schema for tasks with title, description, priority, deadline, completed, user_id"

Cursor generates the SQL migrations and RLS policies. Work component by component and review each before moving on.

Testing with AI
  • TDD: write the test first (you define the behaviour), let the AI implement
  • AI is good at edge cases you'd miss
  • Keep the pyramid: many unit tests, fewer E2E
  • Layers: component → integration → E2E (Vitest + Playwright)

Troubleshooting — quick fixes
AI output is poorCut context, sharpen the prompt, check you're in the right mode
Context window fullNew chat tab; summarize progress and hand it off
useState / event handler errorAdd "use client" at the top of the file
Server Action not runningCheck the "use server" directive
Build fails, dev worksMissing env vars, or server-only code in a static page

Remember
  1. Context is king — strategic @-mentions, clean project structure
  2. Explore → Plan → Build — don't skip the first two
  3. Rules encode your standards — add them only when mistakes repeat
  4. MCP extends Cursor's reach — GitHub, Figma, docs, databases
  5. Git discipline is non-negotiable — commit early, commit often
  6. Try 5 times — rephrase and retry before giving up on a prompt
  7. Production-ready means tests, CI/CD, monitoring and security
  8. Cursor augments your judgment — it doesn't replace it
